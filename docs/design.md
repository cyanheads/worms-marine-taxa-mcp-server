# worms-marine-taxa-mcp-server — Design

## MCP surface

| Tool | Description |
|:---|:---|
| `worms_resolve_taxon` | Resolve scientific names by exact or fuzzy matching, or search one vernacular name, and return accepted-name links. |
| `worms_get_taxon` | Retrieve full Aphia records and optionally vernacular names or sources for one taxon. |
| `worms_get_classification` | Retrieve the complete root-to-tip classification and optionally one page of direct children. |
| `worms_get_synonyms` | List synonyms of the accepted taxon, resolving an unaccepted input first. |
| `worms_get_distributions` | Retrieve distribution records, optionally combined with the accepted taxon's synonyms, and filter the fetched set locally. |
| `worms_get_traits` | Retrieve ecological attributes, retaining hierarchy, sources, and inheritance. |
| `worms_crosswalk_id` | Translate between AphiaIDs and nine external identifier systems. |
| `worms_list_reference` | List identifier systems, taxonomic statuses, habitat-flag semantics, distribution filter values, ranks, or trait definitions. |

All tools: `readOnlyHint: true`, `idempotentHint: true`; omit `destructiveHint`. Set `openWorldHint: true` on every tool, `worms_list_reference` included: four of its topics are static, but the tool's single definition also serves the live ones. No prompts, Apps, SQL workspace, mirror, native helper, harvesting, or user-data writes. The only resources are the published agent skill in root `skills/`, served as `skill://` resources through `createApp({ skills: 'skills' })`; tools alone cover every workflow.

## Overview and requirements

Wrap the keyless [WoRMS REST API](https://www.marinespecies.org/rest/) for name cleaning, taxonomic research, marine distribution inspection, traits, and identifier reconciliation. Its [OpenAPI specification](https://www.marinespecies.org/rest/api-docs/openapi.yaml) is the endpoint and response-schema reference. Use native HTTP rather than another client dependency. Support STDIO and Streamable HTTP, stateless operation without client round trips; upstream credentials are unnecessary. Transport authentication remains framework-managed.

Use per-call retrieval only. [WoRMS terms](https://www.marinespecies.org/about.php#terms) permit attributed text use but prohibit redistributing the entire database without agreement; the [webservice guidance](https://www.marinespecies.org/aphia.php?p=webservice) prohibits complete harvesting and asks users to report their use. No numeric rate limit is published. Images are outside scope. Every result carries the attribution below; retain record citations unchanged. No hosting infrastructure is part of this implementation.

User goals: (1) reconcile scientific or common names, (2) inspect complete taxon records, (3) navigate classification and synonyms, (4) inspect distributions and ecological evidence, (5) reconcile external identifiers. These map to the eight tools above without extra endpoints exposed as tools.

## Shared contracts

### Inputs and normalization

Every input root is a flat `z.object`, never a root union. Describe every field. Validate exclusive modes in the handler before network work, with declared reasons below. Optional strings accept blank/whitespace-only as omitted. Trim scientific-name and vernacular inputs; preserve populated opaque identifiers and evidence filters verbatim. Required nonempty strings reject blanks. Never trim returned scientific text.

`AphiaId` outputs are positive safe integers. Every AphiaID input advertises a number-or-string union accepting the numeric ID, its decimal spelling, or canonical `urn:lsid:marinespecies.org:taxname:<AphiaID>`, with surrounding whitespace removed from strings. Validate the entire selector before extracting its numeric ID; no URLs, foreign namespaces, fractions, nonpositive or unsafe values. Invalid strings name `worms_crosswalk_id` with `externalId` and `type: "lsid"`, or scientific-name resolution. Keep numeric-string and JSON-container repairs working through real transport. External IDs remain opaque nonempty strings, maximum 512 characters; keep their case and punctuation, including complete LSIDs. Type codes normalize surrounding whitespace and case to the exact nine-code enum; do not guess aliases or map GBIF/EOL. Field schemas must advertise accepted spellings, with blank allowed on optional enums and normalized away before mode selection. Statuses, ranks, and match types in output stay open strings, not a closed vocabulary inferred from samples.

Scientific-name elements and vernacular input have a 512-character workload bound. Batch inputs accept nonempty lists without a total-input ceiling and expose zero-based `inputOffset` (default 0), original `inputIndex`, `nextInputOffset`, and `deferredCount`, never copies of deferred values. Validate every submitted element, including deferred positions, before fetching. ID and scientific-name reads send one batch of at most 50 positions starting at inputOffset; WoRMS returns the same match group for a name in any batch, so match-group continuation stays stable and a page can cross any 50-position boundary. Keep duplicate inputs and positional association. Resubmit original arrays and unchanged options. At-end and past-end inputOffset return terminal empty results without requests. `offset` is a positive safe integer, default 1; increment by 50, not by page number. Names use exact matching by default; fuzzy is explicit. `marineOnly` and `extantOnly` default true wherever upstream supports them and are always sent explicitly. Unsupported filters never silently disappear.

### Data models

All listed upstream-derived fields except a validated record's identity may be omitted or null. Preserve omitted versus explicit null; do not replace unknown with empty string, false, zero, a guessed accepted name, or a reconstructed citation. Known upstream integer flags 0/1 normalize to false/true; upstream boolean equivalents are accepted; null stays null and omission stays omission. Unknown flag encodings fail response validation. IDs are integers, not booleans (the OpenAPI `valid_AphiaID` boolean declaration contradicts actual integer responses).

`TaxonRecord` retains **every documented AphiaRecord field**, mapped as follows:

| Output field | Upstream field / type |
|:---|:---|
| `aphiaId` | `AphiaID`, positive integer; required for a present record |
| `url`, `scientificname`, `authority`, `rank`, `status`, `unacceptreason` | Same names, strings |
| `taxonRankId` | `taxonRankID`, integer |
| `validAphiaId`, `validName`, `validAuthority` | `valid_AphiaID` integer, `valid_name` string, `valid_authority` string |
| `parentAphiaId`, `originalAphiaId` | `parentNameUsageID`, `originalNameUsageID`, integers |
| `kingdom`, `phylum`, `class`, `order`, `family`, `genus` | Same names, strings; absent class is not an error |
| `citation`, `lsid`, `modified` | Same names, unmodified strings; do not reformat dates |
| `isMarine`, `isBrackish`, `isFreshwater`, `isTerrestrial`, `isExtinct` | Same names, boolean/null/omitted |
| `matchType` | `match_type`, string |

`Match` contains `aphiaId`, `scientificname`, `authority`, `rank`, `status`, `unacceptreason`, `validAphiaId`, `validName`, `validAuthority`, `matchType`, `url` with the same semantics. Accepted-name fields never fall back to the matched name. `Vernacular` contains `vernacular`, `languageCode` ← `language_code`, and `language`, nullable/optional strings. `Source` contains `sourceId` ← `source_id` (integer), `use`, `reference`, `page`, `url`, `link`, `fulltext`, and `doi`, nullable/optional strings passed through unchanged; `use` (original description, basis of record, additional source, and others) stays an open string. `RankNode` contains `aphiaId`, `rank`, `scientificname`; keep any explicit nulls/omissions other than the identity of a present node.

HTTP 204 means an empty collection or absent record according to the endpoint. Never parse its body. An empty JSON array is equivalent for list endpoints. Batch ID responses preserve literal null and all-null record slots as `found: false`. A nonempty malformed record is an upstream response error, never a miss. A response with incompatible batch length, unexpected IDs, or wrong ordering fails validation rather than pairing a record with the wrong input. A batch-wide 204 yields one missing result per requested item.

### Output, paging, enrichment, and formatting

All eight tools choose whole-item prefixes against the complete paired-surface serialized result, including enrichment (measured per candidate page where it depends on the page), attribution, continuation, and budget disclosure. The shared pager reproduces the lossless formatter and the framework's enrichment trailer, including the blank line it inserts after a field whose last line is a list item, and reserves 1,000 bytes below the 24,000-byte target for transport metadata. Every result exposes `byteBudget: 24000`, `budgetLimited`, and `oversizedItem`. One indivisible scientific row/scalar may exceed the target: return it intact, set oversizedItem true and `requiredBytes` to final paired-surface serialized bytes before transport metadata, and advance continuation. Nested matches, vernaculars, and sources are separate page items; never treat their complete arrays as indivisible. No caches, continuation tokens, new tools, or automatic page walking. Source changes between stateless refetches can change subsequent segments.

Zero-based `resultOffset` (default 0) pages distributions, traits, references, forward crosswalk IDs, and local segments of upstream pages. Outputs include `resultOffset`, `returnedCount`, `totalCount` (known complete local count), and `nextResultOffset` (null when consumed). Filter distributions over the entire fetched set (one synonym window in union mode) before slicing. Flatten traits/definitions completely, and apply the traits measurementType filter, before slicing; nodeIndex and parentIndex remain complete-tree preorder indices, including parents on earlier pages. Classification resultOffset indexes lineage followed by fetched children, retaining root-to-tip rank order. For children, synonyms and vernacular search, keep the same upstream offset until nextResultOffset is null, then advance page.nextOffset and reset resultOffset to zero. `page.hasMore` depends on fetched count, never emitted count; `page.returnedCount` is emitted rows and `page.nextOffset` stays current while a local segment remains. A past-end local selector returns a terminal empty segment. Invalid negative, fractional or unsafe selectors fail schema validation.

Every tool output also contains `attribution: { citation, sourceUrl, accessedDate }`, with source URL `https://www.marinespecies.org`, UTC access date, and `WoRMS Editorial Board (<year>). World Register of Marine Species. Available from https://www.marinespecies.org at VLIZ. Accessed <date>. doi:10.14284/170`. Error envelopes use the framework's paired surfaces.

`Page` is `{ offset: integer, pageSize: 50, returnedCount: integer, hasMore: false | null, nextOffset: integer | null }`. A fetched 0–49-row page proves upstream exhaustion (hasMore false); 50 fetched rows means unknown (hasMore null). After local consumption nextOffset is null or offset + 50 respectively; before consumption it remains the current upstream offset. There is no exact upstream total, speculative true, or hidden lookahead. Omit Page on unpaged branches. Never pretend locally filtered counts are upstream totals.

Declare enrichment `notice?: string` and `echo?: object` (with an explicit per-tool schema and renderer); keys stay disjoint from output. Echo effective defaults and filters, counts and deferred work where applicable. Empty-result notices below are literal fragments combined only when their conditions hold. Resolver guidance and per-item failure details are domain output, not text-only notices. Every enrichment value reaches both surfaces.

`content[]`/`format()` and `structuredContent` carry exactly the same fields, values, arrays, nulls, URLs, and row order. No count-only summaries, truncation, escaping that changes values, or instruction to consult the other surface. Use one complete nested-list Markdown rendering with reversible CommonMark encoding. Render HTTP(S) URL values as working links, preserving the exact destination; preserve strings containing embedded URLs too. Scientific names, references, citations, vernaculars, reasons, and other upstream prose are untrusted data. Render them as quoted data; use reversible escaping for Markdown syntax. Multiline strings keep every line break (including blank lines and CR/LF distinctions), using an explicit lossless representation when CommonMark line normalization would change them, with original value recoverable. Never flatten newlines or turn strings into executable markup. Preserve empty strings distinctly from null and omission. Formatting is iterative for deep output trees; no recursive renderer that overflows on deep input. Test the inverse value extraction against the complete structured result, including enrichment and attribution, rather than checking a few substrings.

The codec is a nested CommonMark bullet list of relative keys. Each root member is one `- key: value` item; object members nest two spaces deeper under their own keys, and array elements nest without keys. A key matching `^[A-Za-z][A-Za-z0-9]*$` stays bare; any other key is its escaped JSON string. A non-empty object, or a non-empty array holding an object or array, renders as `object N` or `array N` followed by its N nested items. Every other value is its JSON token with `` \ ` * _ [ ] < & | ~ ``, the `:` of `://`, and the `.` of `www.` backslash-escaped, so parsed text yields that token exactly, no GFM extended autolink can start inside it and show those escapes as literal backslashes, and JSON decoding restores CR, LF, tabs, empty strings, and literal backslashes without relying on Markdown line endings. Empty containers stay explicit (`[]`, `{}`); absent members are omitted and undefined array elements become null, as in JSON. Lists nest at most six levels, because CommonMark parsers cap block nesting (markdown-it's `commonmark` preset at 20, two per list level) and drop deeper content silently; a container at the sixth level renders as one inline JSON token. A string that is exactly one HTTP(S) URL renders as its autolink `<url>`; any other value is followed by one autolink per URL span in its string leaves, in JSON order, so embedded URLs stay clickable without changing the value. Each enrichment field renders as one root item through the same codec. The inverse parser walks a real CommonMark token stream (markdown-it `commonmark`, no URL normalization) and rejects any token, key form, container count, or autolink the grammar would not produce before comparing the decoded value with `structuredContent`; codec round-trip tests also decode under markdown-it's `default` preset, which adds GFM tables and strikethrough.

## Tools — detail

The shared service errors under **Errors** apply to every networked tool and are repeated inline in each actual definition with `thrownBy: 'service'`. Each tool below lists its additional contract. No expected zero-hit result is an error.

`worms_get_classification`, `worms_get_distributions`, and `worms_get_traits` first read `/AphiaRecordByAphiaID/{ID}` once per call for taxonomic status, the only status source. When the record's `validAphiaId` differs from the submitted ID, `notice` names both numeric IDs and the retry with `aphiaId: <validAphiaId>`. Exact status `alternative representation` selects fixed wording identifying the submitted name as an accepted alternative representation and the linked ID as preferred; other linked statuses retain the unaccepted-name wording. Never interpolate upstream names or status strings into notices. A present record with null `validAphiaId` whose status is not `accepted` gets a notice that no accepted taxon is linked, pointing to `worms_get_taxon`. Accepted, self-valid, and missing records add none. The status fragment precedes any empty-result fragment. Outside distribution union mode the status read is optional: a classified failure returns the evidence with `statusError: ItemError` and no notice, so it never fails a call that would otherwise succeed; rejection, cancellation, and deadline expiry stay atomic. Distribution union uses the same fixed alternative/preferred distinction in its separate notice and continues to retrieve preferred-ID rows and synonyms.

### `worms_resolve_taxon`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `names` | optional nonempty string array, no total-input ceiling | Exact `/AphiaRecordsByNames` with repeated `scientificnames[]`, `like=false`; at most 50 names from inputOffset |
| `inputOffset`, `matchOffset` | nonnegative safe integers, 0 | Original scientific input position and local match position within that group; inactive for vernacular |
| `resultOffset` | nonnegative safe integer, 0 | Local segment of fetched vernacular page; inactive for scientific names |
| `vernacular` | optional string | `/AphiaRecordsByVernacular/{encoded value}`; mutually exclusive with names |
| `vernacularMatch` | `exact`/`contains`, `exact` | Vernacular only, always sent: `like=false` matches a whole recorded common name, `like=true` any recorded name containing the text (SQL `LIKE '%vernacular%'`); blank means exact |
| `fuzzy` | boolean, false | Names only: `/AphiaRecordsByMatchNames`; never fuzz automatically |
| `marineOnly`, `extantOnly` | booleans, true | Names: `marine_only`, `extant_only`; vernacular has no such filters |
| `offset` | integer, 1 | Vernacular only, upstream `offset`; scientific names accept only 1, and the field description says so on this tool alone |

Require exactly one populated selector. Reject `fuzzy=true`, nondefault offset, or nondefault vernacularMatch with names/vernacular in the wrong mode as applicable: scientific names require offset 1 and vernacularMatch exact; vernacular requires fuzzy false. Contains matching keeps `mode: 'vernacular'` and pages like exact matching, 50 rows per upstream offset; exact stays the default because contains is noisier for whole names (`Atlantic cod` also returns *Lepidion eques*, 126493). For vernacular, reject explicitly false marine/extant flags rather than silently ignoring them; echo `marineOnly: null`, `extantOnly: null` because this endpoint cannot filter habitat/extinction. Default true flags do not imply filtering in vernacular mode, and its description states that limitation. Fuzzy sends `match_authority=false` because this surface has no authorship input; echo this effective setting.

Output: `{ mode: 'exact'|'fuzzy'|'vernacular', results: [{ input, inputIndex, matchOffset, partialGroup, matches: Match[], guidance: string|null }], nextInputOffset, nextMatchOffset, deferredCount, page?: Page, attribution }`, plus shared budget/local fields where applicable. Scientific `matchOffset` (default 0) starts within the group at inputOffset; follow both next coordinates against unchanged names. A miss consumes one input. `partialGroup` identifies split fetched groups. Vernacular has one result containing its local segment. Never select one ambiguous match or invent confidence. A full 50-match scientific group still has unknown upstream completeness because the API has no scientific-group continuation; local match paging only exposes the fetched group. Every page whose `results` hold all or part of such a group carries a `notice` naming each such group's `inputIndex` (numbers only, never the submitted name); a page holding none carries no 50-match notice, even when its fetched batch does. The notice names the change that narrows such a group: a fuller name, such as genus plus species epithet, with `fuzzy: false` offered first after a fuzzy call.

Echo `{ marineOnly: boolean|null, extantOnly: boolean|null, fuzzy, offset?, vernacularMatch?, matchAuthority? }`; offset and vernacularMatch appear on vernacular calls only. Empty-name guidance starts with `Call worms_resolve_taxon with the same names and fuzzy: true.` after an exact miss or `Check spelling and call worms_resolve_taxon with corrected names.` after a fuzzy one; while marine filtering is on append `Call worms_resolve_taxon with marineOnly: false to include non-marine taxa.`, and while extant filtering is on append `Call worms_resolve_taxon with extantOnly: false to include extinct taxa.` Both name endpoints apply both filters (fuzzy Trilobita is 204 under `extant_only=true` and 877220 under false), so both suggestions belong in both branches. Vernacular empty/past-end notice, exact: `Call worms_resolve_taxon with vernacularMatch: "contains" to match part of a recorded common name, or with a broader vernacular.`; contains: `Call worms_resolve_taxon with a broader vernacular.` Past offset 1 both end `with a broader vernacular or offset: 1.` instead; at offset 1 that clause would repeat the call that returned nothing.

Additional errors: `invalid_selector` / `ValidationError` when both/neither selector or a normalized vernacular is exactly `.` or `..`; recovery names the exclusive selectors and forbidden dot-only values. `unsupported_mode_options` / `ValidationError` for incompatible options; recovery `Call worms_resolve_taxon with fuzzy and filters for names, or only vernacular, vernacularMatch, and offset for common names.` One request before retries.

### `worms_get_taxon`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `aphiaIds` | nonempty AphiaId input array, no total-input ceiling | `/AphiaRecordsByAphiaIDs`, repeated numeric `aphiaids[]`; at most 50 from inputOffset |
| `inputOffset` | nonnegative safe integer, 0 | Original submitted ID position |
| `vernacularOffset` | nonnegative safe integer, 0 | Local common-name position; inactive without includeVernaculars |
| `sourceOffset` | nonnegative safe integer, 0 | Local source position; inactive without includeSources |
| `sourceUse` | optional evidence string, ≤512 characters | Case-insensitive whole-value filtering of the complete source list before sourceOffset; blank omitted, populated values untrimmed; inactive without includeSources |
| `includeVernaculars` | boolean, false | Only valid when submitted array has exactly one ID; extra request `/AphiaVernacularsByAphiaID/{ID}` for a found record |
| `includeSources` | boolean, false | Only valid when submitted array has exactly one ID and includeVernaculars is false; extra request `/AphiaSourcesByAphiaID/{ID}`, no query keys, for a found record |

Output: `{ results: [{ inputIndex, requestedAphiaId, found, record: TaxonRecord|null, vernaculars?: Vernacular[], vernacularError?: ItemError, sources?: Source[], sourceTotalCount?: integer, unfilteredSourceCount?: integer, sourcesError?: ItemError, guidance: string|null }], nextInputOffset, deferredCount, nextVernacularOffset, nextSourceOffset, attribution }`, plus budget fields. Absent IDs stay in place, record null, guidance `Call worms_resolve_taxon with a scientific name to find an AphiaID.` Singleton enrichment accepts zero-based `vernacularOffset` or `sourceOffset`; follow nextVernacularOffset or nextSourceOffset with the unchanged record/options, repeating the full primary record. The source endpoint is unpaged, so filter the complete fetched list by sourceUse before sourceOffset and byte-budget slicing, refetching on continuation. Preserve all source fields, order, and duplicates. A populated filter matches only a string use with case-insensitive whole-value equality; unknown uses are allowed and null/absent use never matches. Successful source reads report sourceTotalCount for the complete selected list on every segment; add unfilteredSourceCount for the original list only with an effective filter. No counts accompany missing records or sourcesError. No selected rows from a nonempty bibliography suggests removing/changing sourceUse; an empty upstream list points to the returned record's citation and accepted-name link; a past-end offset suggests sourceOffset 0 only when selected rows exist. A list too slow for the 10-second attempt timeout after its retry becomes sourcesError `upstream_timeout`, never a failed call. A vernacular or source 204 is `[]`; no vernacular or source fields when not requested, and nextVernacularOffset and nextSourceOffset are null. A missing record makes no enrichment request. A failed optional fetch retains the taxon plus vernacularError or sourcesError, distinct from empty evidence. All-miss batches succeed. Echo `{ includeVernaculars, includeSources, sourceUse? }`, with sourceUse only when populated and includeSources is true; without includeSources it adds no request, count, or effective echo.

Additional errors, all before any request: `enrichment_conflict` / `ValidationError`, when vernaculars and sources are requested together; recovery `Call worms_get_taxon once with includeVernaculars: true and once with includeSources: true.` `vernacular_batch` / `ValidationError`, when vernacular enrichment is requested for multiple submitted IDs; recovery `Call worms_get_taxon with one aphiaIds entry and includeVernaculars: true.` `sources_batch` / `ValidationError`, the same for sources; recovery `Call worms_get_taxon with one aphiaIds entry and includeSources: true.` One enrichment per call keeps one nested continuation and at most two requests before retries.

### `worms_get_classification`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `aphiaId` | AphiaId | `/AphiaClassificationByAphiaID/{ID}` |
| `includeChildren` | boolean, false | Add `/AphiaChildrenByAphiaID/{ID}` |
| `offset` | integer, 1 | Children's 1-based starting record |
| `marineOnly`, `extantOnly` | booleans, true | Children's `marine_only`, `extant_only` only |

Output: `{ aphiaId, found, ranks: RankNode[], children?: [{ aphiaId, scientificname, rank, status }], page?: Page, childrenError?: ItemError, statusError?: ItemError, guidance: string|null, attribution }`. An unaccepted AphiaID keeps its own lineage, the one WoRMS stores for that usage; the status notice names the accepted ID to call instead. Flatten the complete child chain root first, iteratively without a depth ceiling. No inferred intermediate ranks. A missing classification returns found false, empty ranks, and guidance `Call worms_resolve_taxon with a scientific name to find an AphiaID.` Do not fetch children after that miss. If children were requested but fail, retain ranks and emit `childrenError`, omit children/page. A valid empty children page is `[]` plus exhausted Page, never found false. Echo `{ includeChildren, marineOnly, extantOnly, offset }`; empty children notice at offset 1: `Use worms_list_reference with topic: ranks to inspect rank vocabulary.`; past offset 1: `Call worms_get_classification with offset: 1 to return to the first children page; use worms_list_reference with topic: ranks to inspect rank vocabulary.` No extra domain error beyond shared service errors; options affecting only children are documented as inactive when includeChildren is false. At most three requests before retries (status record, classification, children).

### `worms_get_synonyms`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `aphiaId` | AphiaId | First `/AphiaRecordByAphiaID/{ID}` |
| `offset` | integer, 1 | `/AphiaSynonymsByAphiaID/{accepted ID}?offset=…` |

Output: `{ aphiaId, found, validAphiaId: integer|null, synonyms: [{ aphiaId, scientificname, authority, status, unacceptreason }], page?: Page, guidance: string|null, attribution }`. Use supplied record's validAphiaId, or its own ID only when status is explicitly accepted. Never follow recursive accepted-name chains. A missing record yields found false, validAphiaId null, empty synonyms and resolver guidance. If a present nonaccepted record has no accepted ID, return found true, null validAphiaId, empty synonyms, omit page, guidance `Call worms_get_taxon with the original AphiaID to inspect its taxonomic status; use worms_list_reference with topic: statuses.` Do not label this no-synonyms evidence. A synonym 204 returns empty synonyms with exhausted Page. Past offset 1 the notice is `No synonyms were returned for this page; call worms_get_synonyms with offset: 1 to inspect the first page.`; an empty first page carries no notice. Echo `{ offset }`. No extra domain errors. Two requests before retries; failure of the second fails the operation rather than misreporting absence.

### `worms_get_distributions`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `aphiaId` | AphiaId | `/AphiaDistributionsByAphiaID/{ID}` |
| `recordStatus` | optional `valid`/`doubtful`/`inaccurate` | Trim and lowercase the input before validating; blank omitted; compare exactly against upstream canonical codes and echo the normalized code |
| `establishmentMeans`, `invasiveness`, `occurrence` | optional strings, ≤512 characters | Local case-insensitive whole-value equality, not substring or fuzzy matching; descriptions point to `worms_list_reference` topic `distribution_terms` for observed values |
| `includeSynonyms` | boolean, false | Union mode, below |
| `synonymOffset` | nonnegative safe integer, 0 | Zero-based position in the accepted taxon's synonym list; inactive without includeSynonyms |

Output: `{ aphiaId, unfilteredCount, filteredCount, distributions: [{ sourceAphiaId?, locality, locationId, higherGeography, higherGeographyId, recordStatus, qualityStatus, typeStatus, establishmentMeans, invasiveness, occurrence, latitude, longitude }], synonymUnion?, statusError?: ItemError, attribution }`. Preserve all upstream rows and duplicates that pass the conjunction of filters, in original order. Every row field is nullable/optional; locationId/higherGeographyId map `locationID`/`higherGeographyID`, latitude/longitude map `decimalLatitude`/`decimalLongitude` (finite numbers), other names unchanged. Do not invent coordinates, regions, or invasion status. Null does not match a populated filter.

By default there is no upstream paging or filtering; one bounded-body fetch and complete local filter scan precede resultOffset pagination. 204 means no distributions, not proof the taxon does not exist. Echo only effective filters: recordStatus uses its canonical lowercase code; other populated values remain untrimmed and unchanged. When rows were fetched but none passed the effective filters, the empty notice is `Call worms_get_distributions without filters to inspect recorded distributions, or worms_get_taxon to check the AphiaID.`, followed by `Call worms_list_reference with topic: distribution_terms for observed filter values.` when an establishmentMeans, invasiveness, or occurrence filter is effective. When WoRMS returned no rows, dropping filters returns the same empty set, so the notice is `Call worms_get_taxon to check the AphiaID.` with or without filters. The default status notice also names `includeSynonyms: true`. No extra domain errors beyond the shared contract. Two requests before retries.

WoRMS attaches distribution records to individual name usages, and its taxon page totals an accepted taxon's records with its synonyms'; the endpoint has no parameter to widen this. Union mode (`includeSynonyms`) reads the status record as a required read and resolves the accepted taxon from it (`validAphiaId`, or the ID itself when `status` is `accepted`), so a synonym and its accepted name yield the same rows. A window holds the accepted taxon's rows (only when synonymOffset is 0), then up to 10 synonyms from the one 50-row `/AphiaSynonymsByAphiaID/{accepted}` page containing synonymOffset; 10 divides 50, so a window never spans pages. Sources keep upstream synonym order, rows keep source order, duplicates stay, and every row carries `sourceAphiaId`. `synonymUnion: { acceptedAphiaId, synonymOffset, synonymAphiaIds, nextSynonymOffset, failedSynonyms: [{ aphiaId, error: ItemError }] }` discloses the window, failed reads included in synonymAphiaIds. nextSynonymOffset is synonymOffset plus the window size; a window ending a full page points at the next page start (completeness unknown), and a consumed short or empty page gives null. Filters apply across the window's rows before slicing, and unfilteredCount/filteredCount describe the window; consume nextResultOffset at an unchanged synonymOffset before advancing to nextSynonymOffset with resultOffset 0. Windows are fixed-size, never deadline-adaptive, so each resultOffset continuation re-reads the same window. The record, synonym-page, and accepted-row reads are atomic. Synonym reads run one at a time through the shared pacer; a failed one becomes a failedSynonyms entry through `scope.optionalError`, while rejection, cancellation, and deadline expiry stay atomic. Without a linked accepted taxon (missing record, or non-accepted with null validAphiaId) union mode returns only the submitted ID's own rows at synonymOffset 0 and no rows past it, reads no synonyms, sets acceptedAphiaId and nextSynonymOffset null, and says why in a notice; for a non-accepted ID with a link, the notice states that the rows combine that accepted taxon and its synonyms. A union call makes at most 13 requests before retries (status record, synonym page, accepted rows, 10 synonyms): at least 6 s of start gaps at the 500 ms pacer floor, inside the 45-second deadline. An unbounded union over a 74-synonym taxon would need 78 requests and cannot fit.

### `worms_get_traits`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `aphiaId` | AphiaId | `/AphiaAttributesByAphiaID/{ID}` |
| `includeInherited` | boolean, true | Explicit `include_inherited` |
| `measurementType` | optional string, ≤512 characters | Local case-insensitive whole-value filter, untrimmed; blank means no filter |

Output: `{ aphiaId, unfilteredCount, traits: [{ nodeIndex, parentIndex: integer|null, depth, aphiaId?, measurementTypeId?, measurementType?, measurementValue?, sourceId?, reference?, qualityStatus?, categoryId?, inheritedAphiaId?, inheritedFrom?, parentType? }], statusError?: ItemError, attribution }`. Optional fields also accept explicit null. Map `AphiaID`, `measurementTypeID`, `source_id`, `qualitystatus`, `CategoryID`, `AphiaID_Inherited`; unchanged measurement and reference strings. Type/source/category/inherited IDs accept integer or upstream numeric strings without losing the upstream value. `inheritedAphiaId` preserves the original marker; `inheritedFrom` is that ID only if known and different from the requested taxon, otherwise null. On an accepted taxon WoRMS already returns the attributes recorded on its synonyms, whatever include_inherited is set to, marked by `AphiaID_Inherited`, so `inheritedFrom` can name a synonym as well as a higher taxon. There is no trait synonym union: it would duplicate every synonym node. `parentType` retains the immediate parent's measurementType, including unknown.

Flatten iteratively, depth-first preorder, all container nodes included even if their measurementValue is null. nodeIndex/parentIndex/depth preserve exact topology and sibling order; repeated measurement types and values remain separate. Retain every source and reference; there is no unit field and none is inferred. 204 → `traits: []`. Echo `{ includeInherited, measurementType? }`, the filter only when effective. Empty notice: `Call worms_get_traits with includeInherited: true to include higher-rank attributes; call worms_list_reference with topic: trait_types to inspect definitions.` Do not suggest inherited=true as a guaranteed fix when already enabled.

`measurementType` runs after the tree for the includeInherited setting is flattened (on an accepted taxon that includes synonym-attached nodes) and before resultOffset slicing. It compares with the distribution text filters' rule: case-insensitive whole value, blank means no filter, populated values untrimmed, and a null or absent type never matches. Each match returns with its whole subtree, so qualifiers (`Unit`, `Type`, `Dimension`, `Sex`) stay under the value they qualify, and with its ancestor chain, so every non-null parentIndex in the filtered set refers to a returned node; overlapping matches and shared ancestors appear once, in preorder, with their original nodeIndex, parentIndex, depth, and parentType. `unfilteredCount` (always present) counts the complete tree and `totalCount` the filtered set, so no filteredCount is needed. A nonempty tree with no match gets the notice `No attribute matched measurementType; call worms_get_traits without measurementType to list every recorded attribute, or worms_list_reference with topic: trait_types to inspect type names.`; an empty tree keeps the inheritance notices. Substring matching would conflate `Body size` with `Body size (qualitative)`, and a subtree without ancestors would orphan a `Sex` qualifier from its `Body size` value. IUCN list membership is not a threat category; no category is derived from it. Two requests before retries (status record, attributes); no extra domain errors.

### `worms_crosswalk_id`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `aphiaId` | optional AphiaId | Forward selector |
| `externalId` | optional opaque string | Reverse selector; path-encode entire value |
| `type` | optional nine-code enum | Forward: omitted means all nine; reverse: required |

Exactly one selector after blanks are omitted. Types are `algaebase`, `bold`, `dyntaxa`, `fishbase`, `iucn`, `lsid`, `ncbi`, `tsn`, `gisd`.

Forward resultOffset indexes ordered `(type, identifier)` positions, then rebuilds the ids-by-type shape for each segment. `typeTotals` maps answered types to complete fetched counts: zero means successful absence, positive counts can have empty arrays on a segment, and failed types are omitted. Both per-type and identifier ordering remain unchanged. Reverse resultOffset is inactive; the full reverse record follows the indivisible oversized-item rule.

Output: `{ direction: 'forward'|'reverse', aphiaId: integer|null, externalId?: string, type?: string, found: boolean|null, ids: { [answered type]: string[] }, failedTypes: [{ type, error: ItemError }], record: TaxonRecord|null, guidance: string|null, attribution }`. Forward `/AphiaExternalIDByAphiaID/{ID}?type=…` uses one or nine requests; always send type explicitly. Forward found is null because no IDs cannot prove taxon absence; record null. 204 is a successfully answered type with `[]`, distinct from a failed type omitted from ids. All IDs stay strings, including leading zeros and LSIDs. Preserve per-type array ordering and duplicates. All-types requests use allSettled, scheduled through the shared pacer; deterministic nine-type ordering regardless of completion order. Individual outage/429/timeout failures populate failedTypes when at least one type answered. If all types fail, throw the first failed type's classified service error in the fixed order, with safe failed-type metadata. Cancellation always aborts the entire call, never returns a partial success.

Reverse `/AphiaRecordByExternalID/{encoded externalId}?type=…` returns found true and full record on match, otherwise found false with null record/aphiaId. ids and failedTypes are empty in reverse mode; never spend nine extra calls enriching a reverse match. Empty guidance: `Call worms_list_reference with topic: external_id_types to check the identifier system, or worms_resolve_taxon with a scientific name.` Partial notice names failed types and `worms_crosswalk_id` with a single type retry; echo `{ requestedTypes }` forward or `{ type, externalId }` reverse.

Additional errors: `invalid_selector` / `ValidationError`, both/neither selector or externalId exactly `.` or `..`; recovery names the exclusive selectors and forbidden dot-only values. `missing_external_type` / `ValidationError`, reverse without type; recovery `Call worms_list_reference with topic: external_id_types, then worms_crosswalk_id with externalId and type.` Invalid type schema recovery names the nine allowed values and reference tool. Never expose an unsupported all-types upstream request.

### `worms_list_reference`

| Input | Type/default | Mapping and behavior |
|:---|:---|:---|
| `topic` | required enum | `external_id_types`, `statuses`, `environment_flags`, `distribution_terms`, `ranks`, `trait_types` |

Output: `{ topic, entries: ReferenceEntry[], attribution }` plus shared local pagination and budget fields. totalCount comes from the complete fetched/static list; no implicit filtering. Use topic-specific schemas in the flat output object's entries union, not a union input root:

- external_id_types: `{ code, label, description }`, the nine codes above; IUCN is an identifier, not an assessment/category; GBIF/EOL are unsupported.
- statuses: `{ value, description, group }`, a static guide to the 26 statuses in the [WoRMS manual](https://www.marinespecies.org/aphia.php?p=manual) pick list plus the REST API's technical `quarantined` and `deleted`; label the guide non-exhaustive. Each description is the manual's meaning in one line plus how to read validAphiaId. `group` is additive: `accepted` (accepted, unreplaced junior homonym, nomen protectum, nomen novum, alternative representation; validAphiaId is the record itself, or the preferred name for alternative representation), `unaccepted` (unaccepted and the 15 specific reasons, such as superseded combination and junior subjective synonym; follow validAphiaId, which can be null for nomen nudum), `uncertain` (uncertain, nomen dubium, taxon inquirendum, temporary name, unassessed; validAphiaId is the record itself or null), `technical` (quarantined, deleted; replace a deleted ID with validAphiaId). Records carry the specific reason either as `status` itself or as `unacceptreason` under status `unaccepted`, sometimes on sibling synonyms of one taxon, so a caller tests the group, not `status === "unaccepted"`. `unacceptreason` is free text and stays out of the vocabulary. Do not invent meanings for undocumented statuses.
- environment_flags: `{ field, description, upstreamValues: [0,1,null], interpretation: { zero, one, null } }` for all five flags; null means not recorded, not false.
- distribution_terms: `{ field, description, observedValues }` for `establishmentMeans`, `invasiveness`, and `occurrence`, the values observed across six taxa (444 distribution rows) on 2026-10-20, verbatim; WoRMS publishes no vocabulary for them. Each description states that the list is non-exhaustive and that the worms_get_distributions filter matches a whole value ignoring case. `recordStatus` is already a schema enum and stays out.
- ranks: `/AphiaTaxonRanksByID/-1`; each `{ taxonRankId, taxonRank, kingdomAphiaId, kingdom }` mapped from `taxonRankID`, `taxonRank`, `AphiaID`, `kingdom`, preserving nullable/omitted fields and all rows. Do not hardcode the observed count.
- trait_types: `/AphiaAttributeKeysByID/0?include_children=true`; iterative preorder rows `{ nodeIndex, parentIndex, depth, measurementTypeId?, measurementType?, inputId?, categoryId? }` mapped from `measurementTypeID`, `measurementType`, `input_id`, `CategoryID`; preserve nullable/omitted values and numeric strings. Hierarchy is not flattened away semantically.

Static topics require zero requests; live topics one. Live 204 → empty entries with notice `Call worms_list_reference with the same topic later; use worms_get_traits for recorded taxon attributes or worms_get_classification for actual ranks.` No extra domain errors. No TTL cache is needed initially; avoid stale reference assertions and persistent storage.

## Errors and partial failure

Each tool declares its own inline service entries from this table; do not export one shared errors array. Static reference calls can only raise schema/internal failures. Recovery belongs to the tool, not the transport: a transport failure carries reason, code, and retryable but no hint, the framework fills `data.recovery.hint` from the throwing tool's own `errors[]` entry, and `optionalError` copies that same entry through `ctx.recoveryFor`, so an optional failure for a reason the tool does not declare fails the call. `ItemError` is `{ reason: string, code: number, message: string, recovery: string, retryable: boolean }`, with the same classification and recovery as a thrown error. Partial outcomes are limited to optional children/vernacular/source enrichment, the evidence tools' status read (`statusError`), per-synonym reads in a distribution union (`failedSynonyms`), and multi-type crosswalk. Required reads fail atomically. Never catch cancellation as an item failure. Any `upstream_rejected` input rejection fails the entire tool call, including optional enrichment and any crosswalk type; it is never an outage in `failedTypes` or an optional error field. In crosswalk aggregation, input rejection takes precedence over partial success and all-failed ordering. Stop remaining queued work when this atomic failure is known, settle started work, then throw the classified rejection.

| Reason | Code | When | Recovery, unless a tool overrides it below |
|:---|:---|:---|:---|
| `upstream_rejected` | `ValidationError` | HTTP 400/422 input rejection, regardless of error-body format | `Resolve the scientific name with worms_resolve_taxon for a valid AphiaID, then retry the same tool.` |
| `upstream_rate_limited` | `RateLimited` | HTTP 429, retryable | `Wait for the stated retry delay, then retry the same tool with fewer concurrent calls.` |
| `upstream_access_denied` | `ServiceUnavailable` | Keyless upstream returns 401/403; not caller credentials | `Retry the same tool later; the keyless WoRMS service currently refuses access.` |
| `upstream_unavailable` | `ServiceUnavailable` | Network/5xx or HTML instead of JSON, retryable | `Retry the same tool later; the WoRMS service is currently unreachable or failing.` |
| `upstream_timeout` | `Timeout` | Total deadline or HTTP 408/504, retryable | `Retry the same tool later; WoRMS did not answer within the time limit.` |
| `invalid_upstream_response` | `SerializationError` | Malformed JSON, shape/position mismatch, unexpected endpoint 404 | `Retry the same tool later; use worms_get_taxon to verify a known AphiaID.` |
| `response_too_large` | `ServiceUnavailable` | Response exceeds safety bound, retryable false | `Call worms_get_taxon for the taxon record; this tool cannot return the oversized WoRMS response.` |

A recovery names a step the failing tool's caller can take, and never sends a tool to itself as the alternative. These tools override the defaults:

- `worms_crosswalk_id`, the only tool whose upstream input has a reference vocabulary: rejection `Call worms_list_reference for valid vocabulary, then retry the original tool with corrected inputs.`; outage `Retry the same tool later; use worms_list_reference with topic: external_id_types for offline vocabulary.`; timeout `Retry the same tool later; if type was omitted, call worms_crosswalk_id with one type to reduce crosswalk work.` No other tool carries the one-type narrowing. Recovery hints are static and reach every call of the tool, so a step that fits only some requests states its condition in the text.
- `worms_resolve_taxon`, which has no AphiaID yet: rejection `Correct the submitted names or vernacular, then retry the same tool.`; malformed response `Retry the same tool later; WoRMS returned a response this server cannot read.`; oversized `If several names were submitted, submit fewer per call; for one name or a vernacular, submit a more specific one, or use exact matching if fuzzy: true or vernacularMatch: "contains" was set. This tool cannot return the oversized WoRMS response.`
- `worms_get_taxon`: rejection `Resolve the scientific names with worms_resolve_taxon for valid AphiaIDs, then retry the same tool.`; malformed response `Retry the same tool later; use worms_resolve_taxon with the scientific names to confirm the AphiaIDs.`; oversized `If several aphiaIds were submitted, submit fewer per call. For a single ID, use the record returned beside an oversized common-name or source list, or call worms_resolve_taxon with its scientific name.`
- `worms_list_reference`, whose ranks and trait_types requests carry no caller input: rejection `Retry the same tool later; WoRMS rejected a reference request that carries no caller input.`; malformed response `Retry the same tool later; WoRMS returned a response this server cannot read.`; oversized `Use worms_get_classification for a taxon's ranks or worms_get_traits for its attributes; this tool cannot return the oversized WoRMS list.`

Only documented 204/empty bodies on successful no-content responses are absence; an unexpected 404 is an endpoint failure. Baseline internal/validation/cancellation codes bubble unchanged; caller cancellation is `RequestCancelled`. Schema-invalid input is framework `InvalidParams`, before handler execution; handler mode checks use `ValidationError`. Inline contracts identify service-thrown reasons with `thrownBy: 'service'`. Upstream errors remain untrusted data, with no private headers, stack, or credentials exposed.

## Service, workload, and config

One `WormsService` under `src/services/worms/`, initialized once from setup and accessed lazily. Public service barrel exports the service and domain schemas/types. Tools orchestrate service methods without mocking or wrapping their own logic. Use fixed base `https://www.marinespecies.org/rest/`, explicit path/query allowlists, `URLSearchParams` for repeated array keys, and encoded path segments. No caller-provided host or base URL. Unknown query keys are silently ignored upstream, so no raw query passthrough. There is no field-selection facility.

One shared process-wide pacer permits one active request and at least 500 ms between starts; this is a conservative server policy, not a claimed provider quota. Queue at most 100 pending upstream requests; overflow throws `upstream_rate_limited` with recovery above. All tool calls and retries share it. Never spawn unbounded N+1 requests; maximum logical requests per call are 13 distributions with includeSynonyms (2 without), 9 crosswalk, 3 classification, 2 taxon/synonyms/traits, 1 other live branch. No automatic cross-page walking or scheduled collection.

One 45-second tool deadline covers queue wait, all requests, retry waits, reading, validation, local filtering, and flattening; per-attempt fetch timeout at most 10 seconds and remaining deadline. One retry per logical request, only transient network/429/408/504/5xx/HTML failures, base backoff 1 second with jitter; honor Retry-After only while budget remains. withRetry surrounds the complete fetch/parse pipeline and pacer acquisition sits inside attempts. Thread caller signal and deadline signal through pacing, backoff, fetch, and body reads; check cancellation during iterative local loops at least every 256 nodes/rows. Always dispose timers and release pacer leases; cancellation removes queued work and prevents remaining fanout attempts.

Create the absolute tool deadline once, not a fresh 45-second budget per service call; pass remaining time to each `withRetry` ladder. Expiry of that tool deadline always throws `upstream_timeout`, discards partial results, and cancels queued/in-flight work. Only an exhausted individual request timeout while the tool deadline is still live may become `vernacularError`, `sourcesError`, `childrenError`, `statusError`, a `failedSynonyms` entry, or a crosswalk `failedTypes` entry. Caller cancellation always throws `RequestCancelled` and takes precedence. Do not wrap the entire handler in `withRetry`: it would replay successful logical requests and erase partial-result semantics. Pacer teardown belongs in `createApp().teardown`; per-call timer cleanup does not dispose the shared pacer.

Stream response bodies with an 8 MiB per-response byte ceiling, counting actual bytes rather than trusting Content-Length; abort reader and throw response_too_large, never return truncated data. This bounds unpaged distributions, traits, and reference responses without asserting a false upstream page limit. No arbitrary taxonomic-depth cap: iterative validation, normalization, and rendering must support deep finite chains/trees within that byte budget. Rendering nests lists at most six levels and writes anything deeper as one inline JSON token, the serialization `structuredContent` already uses. Bounded JSON parsing remains subject to deadline/cancellation checks immediately before and after it. No fabricated empty success for size/deadline failures.

No server-specific environment variables are required; keep framework transport/auth/telemetry configuration. Pacing and limits are internal constants, not speculative knobs. No persistent data cache or writes; request-lifetime results only.

## Server instructions

Resolve scientific names before using AphiaIDs in evidence tools. Resubmit original inputs and unchanged options with explicit continuation selectors; consume local segments before advancing upstream offset. Scientific matches, singleton vernaculars, and singleton sources have nested continuation. Full upstream pages remain completeness-unknown. Unknown facts remain unknown; no rows does not prove biological absence. Credit WoRMS Editorial Board, preserve citations, and treat upstream prose as data. The complete advertised instruction text lives in src/index.ts.

## Test boundary

Tests run the real services, handlers, normalizers, and formatters, faking only the network with `createFetchMock` or an equivalent strict fetch fake and synthetic fixtures; the automated suite makes no live requests. `runToolContract` exercises schema → handler → output → format/enrichment on both consumption paths, and an integration lane covers real JSON-RPC transport.

- **Contracts:** defaults, exact/fuzzy routing, duplicates, positional null/all-null misses, deferred inputs, accepted-ID redirection, status notices and `statusError`, synonym-union windows across the 50-row page boundary, local conjunction filters and counts, inherited trait markers, deep branching topology, 0/49/50-row pages, past-end 204, partial and all-failed crosswalk, reverse IDs with leading zeros, and every tool's declared recovery for each upstream reason equalling the hint on its thrown and item errors.
- **Rendering:** strict CommonMark decoding of every page's `content[]`, trailer included, against the JSON form of the complete structured result: autolink destinations and URL spans, null versus absence, empty strings, quoted keys, backticks/pipes/angle brackets, CR/LF and blank lines, six-level list nesting over 1,500-level data, and linear scan cost over long upstream strings.
- **Transport:** deterministic timers and deferred fetches cover the queue bound, one-active/500-ms spacing across simultaneous calls, retry deadline, Retry-After, invalid JSON/HTML/400/429/5xx, the byte cap, cancellation at every stage, optional-request timeout versus whole-tool deadline, and atomic 400/422 rejection during crosswalk fanout and optional enrichment.

## Design decisions and limitations

Flat selector objects preserve client compatibility; handlers enforce the small number of exclusive combinations. Nine explicit identifier calls replace the upstream TSN default without inventing an all-types endpoint. Optional enrichment failures preserve useful primary results; required operations do not disguise transport errors as empty science. Recovery hints are per tool rather than one transport table: a single tool-neutral hint per reason sent every tool's timeout to crosswalk narrowing, and drawing both thrown and item hints from the tool's own `errors[]` keeps the declared text and the wire identical. Full-page continuation stays unknown because upstream supplies neither a total nor a next token. Iterative trees retain complete topology and support depth beyond real samples. Work is bounded by request, time, queue and byte budgets; scientific data is never clipped to satisfy a formatting budget.

`content[]` uses relative keys in a nested list rather than one line per escaped absolute field path. The path form made `content[]` 2.5–4.1× `structuredContent`, and because the 24,000-byte budget counts both surfaces, a `worms_get_taxon` page held three full records; the list form measures 1.2–1.4× and holds nine. A fenced JSON block would be smaller still but leaves URL values as code text rather than links. Scientific-name batches start at inputOffset, as ID batches do, instead of at the 50-aligned window containing it: WoRMS returns the same match group for a name whatever batch carries it, and the anchored batch holds every name the aligned window could still return, so a page never ends short at a 50-name boundary. Each call still sends one batch. Sizing batches to one page would not reduce calls, a window chosen before the fetch underfills sparse pages, and topping a window up would break the one-batch-per-call bound above.

Verification used the official OpenAPI schema and sequential live checks: exact list search, single-record GET, malformed-ID 400, an unknown query key, and a batch containing unassigned AphiaIDs. The unknown key was ignored; sparse null flags, null classification fields, and positional literal-null misses were confirmed. All-null record slots are also treated as absent records.
